## 修复的问题及证据

| 问题 | 修复及回归覆盖 |
| --- | --- |
| 畸形 IPv6、DNS 标签及未转义路径被接受 | 校验压缩段、组数、十六进制与 IPv4 尾部、DNS 标签和路径字符；保留有效地址的解析往返 |
| Client 可将另一个 printer-uri 的请求发往自身端点 | 发送前核对规范化目标，拒绝时传输调用数为零；公开构造的端点在传输层重新校验 |
| 空文档、无效选项仍发起网络预检 | 在任何预检网络访问前验证输入，测试确认没有产生请求 |
| 构造对象可绕过重复属性、状态及版本校验 | 请求/响应校验属性集合与头部；拒绝未定义的 1.2、负状态及冲突目标 |
| 任务状态可用 Integer 或多值伪装，计数可为负 | 任务状态要求一个 Enumeration，计数要求一个非负 Integer；拒绝重复任务编号与歧义字段 |
| media-col 尺寸多值被静默取第一项 | 约束字段单值与类型，拒绝重复成员；同时支持规范允许的可读纸张名称 |
| MIME 大小写及参数被过度拒绝 | 解析带引号/转义的参数，比较参数名及 charset 时忽略大小写；其他参数值保持大小写含义 |
| 标准字符串未执行 UTF-8 字节上限 | 编解码共同校验 Text、Name、ASCII 等类型；验证中文多字节及边界长度 |
| 空属性组、JSON 字节串可消耗过多资源 | 编码、二进制及 JSON 输入均限制属性组，字节字段在分配前校验长度 |
| 扩展值标签被当作短标签读取 | 对尚未实现的扩展布局返回 Unsupported，避免错误解释后续字节 |
| Authorization 可包含控制字符 | 在建立连接前拒绝控制字符、非 ASCII 及全空白值 |
| 上游 HTTP chunk 中途 EOF 行为不正确 | 升级 async 0.22.5，使用真实 TCP 服务发送不完整分块；旧依赖测试失败，新依赖返回 ReaderClosed |
| 最新工具链及 Windows 换行导致 CI 失败 | 移除已废止的无参数 moon install，使用脚本 frontmatter，统一 `.mbtx` 为 LF，并保留全部格式检查 |

测试位置：[边界回归](../boundary_test.mbt)、[客户端回归](../client/client_wbtest.mbt)、[真实 HTTP 测试](../integration/transport_test.mbt)。协议依据：[RFC 8010](https://www.rfc-editor.org/rfc/rfc8010)、[RFC 8011](https://www.rfc-editor.org/rfc/rfc8011)；上游修复依据：[async 0.22.4 → 0.22.5](https://github.com/moonbitlang/async/compare/v0.22.4...v0.22.5)。

## 复现命令

在仓库根目录执行；Windows 需 MSVC C++ 工具及 Windows SDK：

```sh
moon run --deny-warn scripts/verify.mbtx
moon run --deny-warn scripts/verify.mbtx --run version
python scripts/count_source.py --minimum 4001
```

Ubuntu 安装 README 所列 CUPS / Avahi 系统依赖后执行 `python3 scripts/interop_cups.py`。原有计数和 CUPS 脚本继续保留；本次新增自动化使用 `.mbtx`。
