## 本次已修复的问题

- 查询任务不核对响应 job-id，可能误把另一个任务的 completed 当作本次成功；增加身份核对和第一轮等待回归测试。
- Print/Create 成功状态缺少可用任务编号时，调用方可能误认为可安全重试；统一标记 SubmissionUncertain 并保持单次发送。
- printer-uri、job-id、document-format、last-document 的类型/单值约束不严格；增加拒绝错误标签、多值及歧义目标的测试。
- job-id 被放在 requesting-user-name 后，违背 [RFC 8011 目标属性顺序](https://www.rfc-editor.org/rfc/rfc8011#section-3.1.5)；构造器与验证器按第三位 printer-uri、第四位 job-id 修复，检查实际编解码顺序。
- CLI 的 1 MiB JSON 输入限制无法承载正常文档的十六进制表示；按文档/消息预算调整有界输入限制，独立构造 1,048,832 字节二进制文档并验证完整往返。

修复前客户端新增回归测试失败，类型/单值校验新增测试失败；修复后全部通过。新增验收覆盖实际失败路径和独立服务交互，不用于机械增加代码量。
